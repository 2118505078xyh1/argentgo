// 若包含 '|'，则视为枚举选项，如 `dev|stage|prod` 或
// `[dev|stage|prod]`；每个备选项都是一个候选。像
// `<env>` 或 `[file]` 这样的普通占位符描述开放取值，不产生候选。
// CompleteArgument 返回 cmd 的 argument-hint 中以 argPrefix
// 开头的候选值，按提示中的顺序排列。匹配不区分大小写且
// 按 rune 安全处理（全角 ASCII 折叠为半角，因此 CJK 输入法可用），但
// 返回的字符串是未经改动的候选，可直接插入。
//   - 空的 argPrefix 匹配所有候选，因此一个函数同时服务于
//     空查询列举和增量补全。
//   - 以空白分隔的提示标记各自独立检查；含 '|' 的标记
//     贡献其备选项，其余被忽略。
//   - 拆分前去掉一层可选的 <...> 或 [...] 包裹，因此
//     `[a|b]` 和 `a|b` 都能被识别。
//   - 空备选项和重复项被丢弃；少于两个不同值的组
//     不算枚举，予以忽略。
//   - 没有提示，或提示只含开放占位符的命令没有候选，
//     返回 nil；候选非空但无一匹配 argPrefix 时
//     同样返回 nil。
// argumentKey 规范化候选或用户键入的前缀以便比较。
// 与 completionKey 不同，它保留 '/' 和内部空格：参数可能是
// 路径或多词取值。
// argumentCandidates 从 argument-hint 中提取枚举值。
// 含空白的值无法通过参数提示往返传递，
// 因此在简单候选少于两个时会进入第 3 级（标识符）。
// 按大小写折叠的排序键，以原字符串作并列决胜项，去除
// 完全重复项；每次调用都会产生相同顺序。
// "/cmd ze" 形似命令，但没有名为 "cmd" 的命令，所以第 1 级
// 失败，末尾标记通过第 2 级补全。
// 补全协调器：在扁平的可用字符串池之上，
// 按 aider 风格进行三级回退。
// CompleteCommands 和 CompleteArgument 被刻意设计成单一用途的纯
// 匹配器（一边是命令名，另一边是枚举的参数值）。
// Complete 用 aider 在其输入组件中采用的回退顺序将它们串联起来，
// 这样前端只需一次调用，不必在每种
// 语言绑定中重新实现规范化以及"当前适用哪个列表"的判断。
// 这里不读取文件、不启动进程，也不修改
// 调用方的切片。
// Complete 返回从 available 中抽取的、针对 input 的补全候选。
// 依次尝试三级；第一个产生匹配的级别
// 胜出，因此歧义前缀会返回整组匹配项（即
// 下拉框需要渲染的"歧义列表"）。各级别如下：
//  1. 命令名 —— 当 input 以 '/' 开头时，将可用字符串
//     视为斜杠命令名，并用 CompleteCommands 匹配。
//     这复用其前导斜杠处理、大小写/宽度折叠、CJK 安全的 rune
//     匹配和别名规则；与 CompleteCommands 一样，部分键入的
//     参数（"/rev --all"）不会抑制名称匹配。
//  2. 命令专属候选 —— 末尾标记（或命令之后的标记，如 "/deploy st"）
//     命令，如 "/deploy st"）通过 available 匹配，使用
//     CompleteArgument 的枚举值规则。完整斜杠命令后的
//     尾随空格（"/deploy "）产生空前缀，即匹配所有候选。
//  3. 标识符 —— CompleteArgument 无法表示的取值（含空白或 '|' 的
//     取值，或单个候选）按普通的、CJK 安全的
//     前缀匹配。这是 aider 对文件名和聊天标识符的回退方案。
// 匹配不区分大小写且会折叠宽度（全角 ASCII 与表意空格的表现
// 与半角形式一致），因此中文输入法在每个级别都
// 可用。结果经过去重，并按折叠后的小写值稳定排序，
// 原字符串作为并列时的决胜项；nil 或空输入
// 会列出 available 中的全部内容。返回的切片是全新的，
// 绝不与 available 共享底层数组。
// 级别 1：CompleteCommands 忽略第一个标记之后的任何内容，因此
// 部分键入的参数（"/rev --all"）仍能补全名称。
// completeCommandNames 将扁平的候选池适配给 CompleteCommands：
// 把每个字符串包装成命令名，再将匹配结果映射回名称。
// completeArgumentNames 将扁平池适配给 CompleteArgument：
// 把它编码为一个枚举的 argument-hint 组。含空白或 '|' 的
// 值无法通过提示标记往返传递，因此这类值留给
// 标识符级别处理。一个组至少需要两个不同值才算枚举；
// 单个候选同样交由标识符级别处理。
// completeIdentifiers 是第 3 级：使用与参数补全相同的折叠、
// 不区分大小写的键做普通前缀匹配。它保留 '/' 和内部
// 空格，因此路径和多词标识符能得到合理的补全。
// lastToken 返回 s 中最后一个空白 rune 之后的部分。
// sortedUnique 返回按折叠键排序的新切片（原字符串作并列
// 决胜项），并去除完全重复项。它从不修改输入。
// 刻意使用未排序的输入：某条命令同时按名称和别名匹配，
// 另有两条来自不同路径的命令同名。
// 通过别名匹配的 "review" 命令必须恰好出现一次。
// 命令名补全。
// CompleteCommands 是针对斜杠命令的纯前缀匹配器：它从不读取
// 文件、启动进程或修改其参数。它让 UI 能够提供
// 实时建议列表，而无需在每种前端中重新实现本包的命名规则
// （命名空间、frontmatter 别名、CJK 输入）。
// CompleteCommands 返回所有 Name 或 Aliases 以 prefix 开头的
// 命令。匹配规则：
//   - 忽略前导 '/' 和首尾空白，因此像 "/rev" 这样输入了一半的
//     斜杠命令可直接使用。
//   - 只考虑 prefix 的第一个以空白分隔的标记；名称后
//     部分键入的参数不会抑制匹配。
//   - 比较不区分大小写且按 rune 安全处理（多字节 CJK 名称会
//     折叠为半角形式，覆盖中文输入法的输入）。
//   - frontmatter 中声明的别名同样匹配。对插件命令，别名还可
//     带命名空间匹配，例如 "acme:review" 的别名 "re"
//     可通过 "acme:re" 访问。
//   - 空 prefix 匹配所有内容，因此一个函数既能用于
//     空查询列举，也能用于增量补全。
// 结果是按 Name（并列时再按 Path 保证稳定）排序的新切片，
// 即使某条命令通过多个名称匹配，也绝不包含重复项。
// Complete 是 Set 对 CompleteCommands 的便捷封装。
// completionKey 将用户键入的前缀或命令名/别名规范化为
// 单一的可比较形式。宽度折叠在大小写折叠之前逐 rune 进行，
